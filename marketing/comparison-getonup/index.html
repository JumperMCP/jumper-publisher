Hosting

One server, many deploys.

A self-hosted Worker and R2 bucket a whole team can share. Also runs locally on Miniflare.

One install, yours alone.

Lives in your own Cloudflare account, free or paid. Each website gets its own Worker and address.

Interface

CLI first.

A snippet in AGENTS.md lets any coding agent run getonup deploy. Also has a local stdio MCP server.

Chat first.

A remote MCP connector for ChatGPT, Claude and Codex, plus a web Cockpit. Claude Code can connect too.

What you hand it

Raw source is fine.

Bare .tsx, .vue or .js gets wrapped with React 18, Babel, Tailwind and esm.sh. HTML and built folders work too.

Finished files.

HTML, CSS, JS and images, or a ZIP, including built React or Vue output. Source files are served, never run.

Going back

Overwrite or start fresh.

--id overwrites a stable URL. Otherwise every deploy gets a new throwaway link.

A 20-version undo.

A persistent project, a safeguard against oversized rewrites, and protection when two chats edit one site.

pants-math.you.workers.dev

A separate origin for every site. Your own domain takes a manual step in Cloudflare.

Setup

Developer setup.

Clone, create an R2 bucket, set a token, npm run deploy, getonup login. Public instances need a WAF rate limit.

Guided install.

A browser installer, one Cloudflare API token in your Publisher, then your MCP URL in your AI client.

Limits

20 MiB, 300 files.

Per deploy, and both are defaults you can change in your server config.

20 sites, 25 MB each.

Files up to 10 MB each. Sites share your Cloudflare account's allowance.

Using both

Start in the scratchpad, then promote what you keep.

The scratchpad phase

You work in a terminal or IDE, or run agents from scripts.

An agent writes a bare Dashboard.tsx and getonup returns a preview URL with no project setup. A throwaway CodePen for AI output: links are public, and getonup serve stays on your machine.

The lifecycle phase

You talk to chat agents, or want sites to persist in your own account.

Publisher keeps revisions in a SQLite Durable Object. Weeks later, a new chat can “change the button to green”, and you can roll back if the agent breaks something.

When both make sense

Exploring, then demoing

getonup while an agent tries UI ideas. Publisher once the finished bundle needs a home, revisions and edits from chat.

Agents in several places

Terminal agents call getonup from AGENTS.md. Web and mobile chat agents reach Publisher through an OAuth MCP connector.
